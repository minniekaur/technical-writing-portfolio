# Using This Portfolio in an Interview

## 60-second walkthrough

Start with the migration sample. Explain the audience, why the workflow separates QA from UAT, and how the documentation creates clear handoffs. Then show the API sample to demonstrate developer-facing writing and OpenAPI. Finish with the AI knowledge framework to show information architecture and governance beyond traditional documentation.

## Questions to be ready for

### “Is this production documentation?”
These are original portfolio samples based on generalized enterprise scenarios. I intentionally removed proprietary names, data, architecture details, and internal processes while preserving the documentation problems and methods I wanted to demonstrate.

### “How do you work with SMEs?”
Describe how you identify the source of truth, capture assumptions and open questions, validate technical steps with the appropriate SME, and use review history/acceptance criteria to make approval explicit.

### “Why docs-as-code?”
Discuss reviewability, version history, proximity to engineering workflows, automated checks, and reusable structured content—while noting that the tool should fit the audience and publishing model.

### “How do you measure documentation?”
Use measures appropriate to the goal: task success, support deflection, search success, content freshness, review SLA, adoption, developer time-to-first-success, and qualitative feedback. Avoid treating page views alone as proof of effectiveness.
